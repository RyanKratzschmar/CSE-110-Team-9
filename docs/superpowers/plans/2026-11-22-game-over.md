# Game Over Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** End death/quit flows at a dedicated Game Over screen with restart and menu actions.

**Architecture:** Add a stateless Konva view and controller, registered in App through a `gameover` Screen route. Reuse GameSession for ending and resetting a run and preserve existing navigation/music cleanup.

**Tech Stack:** TypeScript, Konva, Vitest/jsdom; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-22-game-over-design.md`

## Global Constraints

- Play Again resets the shared game and opens floor 1; Main Menu opens the title.
- Death by answer and potion counterattack must both reach Game Over.
- Expose `switchToScreen({ type: "gameover" })` for the teammate's quit button.
- Keep the patch limited to the new screen, navigation, combat exits, and tests.
- Leave changes uncommitted and unpushed unless requested.

## Review Focus

- Positive-HP quit: opening Game Over must end that run too (Task 1).
- Restart: no HP, inventory, or progression leaks from the ended run (Task 1).
- Main Menu: returning must not silently start a fresh run (Task 1).
- Lethal potion: no delayed navigation can interrupt a new run (Task 2).
- Wins: still advance to the map rather than Game Over (existing Task 2 tests).
